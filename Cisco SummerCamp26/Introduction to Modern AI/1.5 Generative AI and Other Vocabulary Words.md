# 1.5 Generative AI and Other Vocabulary Words

## 1.5.1 Part 1

**Why vocabulary matters:**

- Word salad: too many terms thrown at you at once (transformers, GPT, GPUs, quantized/distilled/pruned models, foundation/base/instruction-tuned models, RAG, agents)
- This unit sorts the terms into an understandable mental map

**Generative vs. non-generative AI:**

- **Non-generative**: outputs one of a predefined set of answers or a number
  - Image classifier: outputs one of predefined classes (panda, dog, bird)
  - Sentiment analysis: positive / negative / neutral
  - Life expectancy prediction: outputs a number
- **Generative**: creates new content that didn't exist before
  - Image generator: creates a new image
  - Text summarizer: free-form summary in its own words
- Other names for non-generative: discriminative AI, predictive AI, supervised learning, traditional AI
- Generative models' outputs can feed other models (writer → editor; image generator → image classifier)

**Expectations differ:**

- Non-generative: one correct answer, or selection from an existing set (like a multiple-choice question)
- Generative: many possible new answers - infinitely many (like an open-ended essay)
- Examples per task:
  - **Machine translation**: dictionary lookup = non-generative; translating phrases/sentences = generative
  - **QA**: extracting from a document = non-generative; answering in own words/knowledge = generative
  - **Summarization**: own words = generative
  - **Text classification**: predefined labels = non-generative; open labels (e.g., sports categories in a forum) = generative
  - **Qualitative scoring**: just a number = non-generative; criteria + explanations = generative
- Benefit of non-generative: controlled outputs - e.g., "answer only yes or no" for downstream software

**Generative model types:**

- **LLMs** (text)
- **Diffusion models** (images): Stable Diffusion, DALL-E 3, Emu (Imagine)
- **Adversarial networks**: an older approach (generator vs. discriminator)

**Sequence models:**

- Process sequences of elements: text, DNA/RNA, time series
- **RNN (Recurrent Neural Network)**: processes one word at a time, in series - correct but slow for long sequences
- **Transformer** (introduced by Google in 2017): processes words in parallel - much faster, handles long sequences
- Transformer is the foundation of modern LLMs

**From task-specific to foundation models:**

- **Task-specific models**: one model per task (translate, summarize, sentiment)
- **Foundation models**: one model, many tasks via prompting
- Training: predict the next word (language modeling) - labels are free because the next word already exists in the text
- **Base model** (pre-trained): the raw next-word predictor (e.g., "a city I want to visit for a vacation is...")
- **Instruction tuning**: additional training on curated instruction + response examples → **instruction-tuned model** - the kind you use with chatbots
- **GPT = Generative Pre-trained Transformer** - generative (creates text), pre-trained (trained on internet text), transformer (architecture)

## 1.5.2 Part 2

**Model compression:**

- **Quantization**: store parameters in fewer bits (32 → 16 → 8), using less space and memory
- **Distillation**: a big model teaches a smaller model - the big model's outputs become the labels for training the small one
- **Pruning**: set unimportant parameters to zero (like trimming leaves from a plant), making the model smaller

**Hardware:**

- **CPU**: the computer's brain - good at sequential tasks
- **GPU**: parallel math specialist (games, graphics, ML training and inference)
- GPUs excel at the matrix math used in machine learning

**RAG (Retrieval Augmented Generation):**

- Solves: hallucinations, private company documents, context window limits
- How it works:
  1. Documents are chunked; chunks' embeddings stored in a **vector database**
  2. User question → embedding → similarity search against the database
  3. Relevant chunks retrieved → sent to the LLM along with the question
  4. LLM answers grounded in the retrieved content
- **Grounding**: retrieving source-of-truth information so the model's answer is based on real data

**Fine tuning:**

- Additional training on domain-specific data (knowledge, tone, safety)
- Base model → fine-tuned model for your domain
- Distinct from instruction tuning (general instruction following)

**Agents:**

- An LLM wrapped in code, with extra capabilities:
  - **Reflection**: the agent checks its own work
  - **Tool use**: web search, calendar, etc.
  - **Planning**: multi-step goals (e.g., preferences → destinations → flights → book)
  - **Collaboration**: multiple AI agents working together
- Treat this list as a reference for further reading

## 1.5.3 Skill Stacking

**The idea:**

- Instead of mastering one skill, combine two or more - the unique combination stands out
- Utensils analogy: spoon, fork, knife, chopsticks - each is right for a different meal; combining them covers more situations

**Examples:**

- Technical + creative skills make you stand out
- Photography + zoologist → picture book author
- Dance + videographer → dance video creator
- Video editing + marketing → marketing videos
- Art + coding → game designer
- Writing + programming → technical writer
- Jokes + teacher → engaging classes
